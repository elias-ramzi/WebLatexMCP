Claude for scientific writing

public beta · v0.7.1 · github.com/elias-ramzi/WebLatexMCP

WebLatexMCP: an MCP server that lets Claude read, edit, compile and push your LaTeX paper — Overleaf, GitHub, or a plain local folder. Public beta, MIT licensed.

Motivation

Write papers straight from Claude

No more copy-pasting paragraphs between a chat tab and Overleaf. Claude works on the real project: it reads the .tex, edits it, compiles it, and looks at the typeset page.

Write & rewrite

Rewrite the paragraph you point at; turn experiment results into a table or a figure.

Discuss citations

Search and check references against DBLP, Crossref and OpenAlex — never typed from memory.

Comment the draft

Select text in the PDF, leave a note, and Claude edits the matching source line.

Hunt for typos

Bundled skills proofread, review against a writing guide, and prepare the arXiv upload.

You stay the author: every change comes back as a diff, and nothing reaches Overleaf until you say so.

The pitch: Claude as a co-author on the actual project, not a chat window you copy text in and out of. Four things it does well: writing, citations, acting on review comments, and proofreading.

Getting started

Requirements

Always

  • Node.js ≥ 20 (npm / npx)
  • git ≥ 2.25 — gh optional
  • macOS, Linux or Windows (WSL included)

TeX is optional: editing, syncing and the PDF viewer work without it. Only compile needs a backend.

TeX Live + latexmk

  • What Overleaf runs — the closest match
  • Several GB for a full install
  • Errors come back with the 5 source lines around them

Tectonic

  • One lightweight binary, fetches packages on demand
  • Output can differ slightly from Overleaf
  • No source snippets on errors

Not sure what is installed? Ask Claude to run doctor. A missing default backend falls back to the other one — and says so; a backend you chose never does.

Checked against the install guides: Node 20+, git 2.25+. TeX only for compile. latexmk is the default and what Overleaf uses; tectonic is the light option. doctor reports engines, the TeX distribution and where packages can be installed.

Review

Becoming the reviewer

  1. viewer opens the PDF in your browser or a VS Code tab pdf.js on 127.0.0.1 — the PDF never leaves your machine.
  2. It hot-reloads on every compile and keeps your page and scroll position.
  3. Select text in the PDF and leave a note.
  4. SyncTeX maps the selection back to its source file:line.
  5. Ask Claude to act on them please resolve comments list_comments hands Claude each note, the quoted text and the 5 source lines around it; it edits, then resolve_comments clears the markers.
The viewer is a small local web server started on demand. It polls for a new build and reloads in place. Comments are working notes for the session — kept in memory, not written anywhere. SyncTeX is what turns a click on the PDF into a source line.

Figures

Figures in TikZ, drawn by Claude

  1. Describe the figure — or paste a sketch draw the architecture as a TikZ figure
  2. Claude writes the TikZ into the paper and compiles it The figure is LaTeX source: fonts and colours match the paper.
  3. render_pages lets it see the result The page as a picture, found by the figure's label — Claude looks at it as you would.
  4. pdf_geometry measures what the eye misses Boxes in points: a label over a frame, a figure past the margin.
  5. It fixes what it saw, recompiles, and looks again.

A figure is source, not a picture — every revision is a diff you can review.

No more exporting from a drawing tool and re-uploading a PDF. Claude writes the figure in TikZ, compiles, then renders the page to look at it — overlaps, arrows crossing labels, text too small. pdf_geometry gives the exact boxes when looking is not precise enough.

References

Citations, checked — not trusted

Search

search_references asks DBLP, then Crossref, then OpenAlex. A substitute is always reported; a source you pin is never swapped.

Add — gated

add_citation re-fetches the canonical BibTeX from the service, server-side. The entry text never comes from the model; plain edits to a .bib are refused without your explicit OK.

Report

check_citations finds undefined, uncited, duplicate and incomplete entries — in a .bib, a thebibliography, or a prose list. /verify-citations checks each title, author list, venue and year.

Caveat

dblp.org now sits behind an anti-bot challenge, so today Crossref and OpenAlex do most of the work.

Three backends behind one resolver. The key point is the gate: a BibTeX entry is fetched from the issuing service, so it cannot be hallucinated. OpenAlex publishes no BibTeX, so its records are fetched from Crossref by DOI, and a record with no DOI is refused.

Ongoing work

A peer review before the real one

An independent panel of Claude models reviews the paper; a triage agent checks every finding against the paper and writes one review. /review-paper my-paper NeurIPS

Your paper

  • compiled once
  • sources + PDF
→

Independent panel

  • 3 full reviews — Sonnet, Opus, Fable
  • a devil's advocate
  • a novelty scout
  • typo hunters, one per file
→reports

Triage

  • reads the paper first
  • merges duplicates
  • verifies each finding in the paper
  • drops the false positives
→

One review

  • summary, strengths
  • weaknesses, ranked
  • questions, typos

Independent

No reviewer sees another's report, so agreement between models means something.

Verified

A finding is kept only once it is checked in the paper — appendix included.

Read-only

It reviews, never edits: the reports stay in a local, git-excluded folder.

Ongoing — /review-paper is on dev, not yet released.

Work in progress: the /review-paper command and the peer-review skill are on dev, not yet released. The three full reviews are blinded — the triage does not know which model wrote which. The design page has the details: severity, fixability and confidence per finding, and the triage log with a verdict for each one.
